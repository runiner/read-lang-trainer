# rus-lang-trainer

Детское веб-приложение для обучения чтению русских слогов. Rust → WebAssembly, UI на TypeScript + Vite.

## Запуск (dev)

```bash
# 1. собрать wasm (один раз / после правок в crates/)
HOME=/tmp/phantom ./tools/wasm-pack build crates/wasm -t web   # результат: crates/wasm/pkg
rm -rf web/pkg && mv crates/wasm/pkg web/pkg

# 2. запустить UI
npm --prefix web install
npm --prefix web run dev    # сам пересобирает wasm; http://localhost:5173
```

Примечание про `HOME`: бинарь wasm-pack при сборке пишет во временные каталоги внутри домашней директории; в песочнице с ограниченной записью это обходится подменой HOME. Вне песочницы запускайте просто `./tools/wasm-pack build crates/wasm -t web`.

## Проверки

```bash
cargo test -p rus-core              # логика: контент, план сессии, скорость чтения
npm --prefix web run test           # vitest: история + интеграционный прогон цикла
cd web && npx tsc --noEmit          # типы
```

## Как добавить упражнение

Контент — в JSON-документах, Rust-код при этом менять не нужно:

- `content/levels.json` — короткие уровни, ключи `vowels`, `simple-syllables`, `syllables`, `words`, `phrases`; значение — массив строк для чтения вслух. Добавить слово = дописать строку: `"vowels": ["а", "о", ...]`.
- `content/stories.json` — уровень «текст»: массив произведений `{"id", "title", "author", "parts": [...]}`; каждый элемент `parts` — одно упражнение (часть истории), читаются по порядку.

После правки: `cargo test -p rus-core` (проверит схему и содержимое: непустые уровни, уникальные id, ≥2 частей у произведения, только кириллица с разрешённой пунктуацией; битый JSON даст явную ошибку).

**Важно:** контент «запекается» внутрь wasm-бинаря на этапе компиляции Rust (`include_str!`), поэтому после изменения JSON его нужно пересобрать. Команды `npm --prefix web run dev`, `run test` и `run build` делают это сами (скрипт `build:wasm` → `web/wasm-build.mjs`). Если dev-сервер уже запущен — остановите и снова выполните `npm --prefix web run dev`. GitHub Actions пересобирает wasm на каждом пуше.

Свежесть артефакта контролируется автоматически: встроенный идентификатор версии контента (`content_version()` = SHA-256 от байтов обоих JSON) сверяется тестом `web/src/freshness.test.ts` — несоответствие собранного pkg и файлов ловится `npm --prefix web run test` и CI. Изменение байтов документа (даже reformat без смены текста) = новая версия.

## Публикация (GitHub Pages)

CI/CD: [.github/workflows/deploy.yml](.github/workflows/deploy.yml) — на push в `main` гоняет `cargo test` + `vitest`, собирает wasm-pack → Vite и публикует `web/dist` на GitHub Pages; на PR — только тесты/сборка.

Разовые шаги (только в веб-интерфейсе GitHub): создать публичный репозиторий, `git remote add origin … && git push -u origin main`, в **Settings → Pages** выбрать Source: **GitHub Actions**.

Локально собрать статику: `npm --prefix web run build` → `web/dist`.

## Структура

- `crates/core` — чистая Rust-логика (уровни, база примеров, генерация сессий, статистика). Тестируется без браузера.
- `crates/wasm` — прослойка wasm-bindgen над core.
- `web/src/wasm.ts` — единственная типизированная граница JS→wasm.
- `web/src/history.ts` — localStorage-адаптер истории сессий (cap 500).
- `openspec/` — спецификации и изменения (process: OpenSpec, см. AGENTS.md).

## Настройки отображения

В окне настроек: блок «Методика» (что делает программа и роль взрослого), выбор шрифта из трёх читаемых стеков и переключатель «Прописные / Строчные». Шрифт, регистр и состояние блока запоминаются в localStorage (`rus-trainer.preferences`) между запусками; количество упражнений и уровень каждый раз выбираются заново. Регистр меняет только начертание — статистика считает символы исходного текста.

## Как играть

Открываете приложение → настройки сессии (количество упражнений 5–50, уровень: гласные / простые слоги / слоги / слова / фразы / текст) → «Начать».

Уровень **«текст»**: тексты басен (Крылов) хранятся уже размеченными — одна строка = одна часть. Взрослый выбирает произведение, и количество упражнений задаётся самой разметкой (поле размера становится неактивным и показывает число частей). Части идут по порядку, за занятие ребёнок читает историю целиком; на экране упражнения видно название и номер части. Ребёнок читает вслух, взрослый подтверждает прочтение пробелом, кнопкой «Далее» или тапом по экрану. После последнего упражнения — статистика (включая скорость чтения в символах в минуту); история сохраняется локально в браузере.
