# Design

## Context

Уровни и генерация сессий живут в `crates/core`: `Level::examples()` → статические массивы `content.rs`, план строит `session_plan` (Fisher-Yates + cycle) в [session.rs](../../crates/core/src/session.rs), сессию ведёт `Session`, итог — `SessionRecord`. UI выбирает уровень через select в `web/src/main.ts`, фасад `create_session(level, size, seed)` принимает level-id строкой. См. proposal.md — зачем нужен уровень «текст».

## Goals / Non-Goals

**Goals:**
- Разбиение текста — чистая функция core, детерминированная, тестируемая без браузера.
- Существующие пять уровней не меняют поведение.
- UI: минимальный conditional контрол «Произведение», без редизайна экрана настроек.

**Non-Goals:**
- Загрузка текстов из файла/сети, редактирование произведений, прогресс «сколько глав уже прочитано» между сессиями.
- Подсветка прочитанного, озвучка.
- Автоматический подбор «подходящего по сложности» текста — взрослый выбирает сам.

## Decisions

1. **Модель контента.** Новый модуль `crates/core/src/stories.rs`: `Story { id, title, author, text }`, статический `STORIES: &[Story]` (6–10 произведений). `Level::Text` существует для совместимости enum, но его «примеры» не плоский список, а произведения; `examples()` для Text возвращает пустой срез, а планирование идёт отдельной веткой. Альтернатива «разбить тексты на предложения заранее и хранить как обычные примеры» отвергнута: разбиение зависит от N, предзаготовка невозможна.
2. **Алгоритм сплита.** Текст режется на предложения (границы `.!?…` + дефисные диалоги обрабатываются грубо: только терминаторы, кавычки остаются внутри). Затем жадная раздача предложений по частям: цель каждой части — `total_chars / N`, переход к следующей части, когда накоплено ≥ цели с учётом остатка (чтобы последняя часть не оказалась пустой). Ровно N частей, ни одна не пуста при N ≤ числа предложений. Детерминированно, без RNG.
3. **Валидация N против предложений.** `Session::new` для Text требует `size <= sentences.count`; иначе panic в debug-сборке заменяем явной ошибкой: plan возвращает `min(size, sentences)` частей? Нет — спека требует сообщать до старта. Решение: core отдаёт `story_sentence_count(id)`, UI показывает максимум и блокирует старт; `create_session` при нарушении обрезает N до числа предложений (страховка, UI должен ловить раньше).
4. **Сигнатура фасада.** `create_session(level, size, seed, story_id)` — четвёртый параметр, для не-Text игнорируется. Пустая строка + level="text" = ошибка, которую UI не должен допустить (см. spec). Альтернатива «level = "text:voronon-i-volchok"» отвергнута: парсинг составных id в двух местах хуже явного параметра.
5. **Seed для Text не используется** — порядок фиксирован чтением истории; параметр остаётся в сигнатуре ради единого вызова.
6. **Тексты.** Берём public domain: Крылов («Ворона и Лисица», «Воробушек и голубь» в прозаической пересказанной версии? — нет, басни как есть), Барто (цикл «Игрушки» как набор коротких текстов), Мамин-Сибиряк «Верное сердце», Гаршин «Лягушка-путешественница» (сокращённая версия — риск: держим оригинал целиком для длинных, короткие целиком). Точный список фиксируется на этапе задач; каждый текст ≤ ~1500 символов, чтобы 5 упражнений читались за занятие.
7. **UI.** Select уровня += «текст»; при выборе Text под ним появляется `<select id="story">` со списком «Название — Автор», справа счётчик «макс N частей: <count>», обновляется при смене произведения; кнопка «Начать» неактивна без выбранного story-id или при size > count (с подсказкой). Предпросмотр показывает начало первой части.

## Risks / Trade-offs

- [Грубый сплит по пунктуации ломается на «...» и диалогах в кавычках] → тесты на реальных текстах басен; допускаем части с лишними пробелами, потеря содержимого недопустима и покрыта тестом склейки.
- [Длинные тексты → огромные куски при малом N] → adult-facing ограничение решено выбором: размер сессии минимум 5, значит каждая часть ≤ ~300 символов для текстов ≤1500.
- [Обрезка N в create_session расходится с подсказкой UI] → оба берут число предложений из одной функции core; UI-тест сверяет.
- [wasm-размер от текстов] → десятки КБ, приемлемо; при росте библиотеки — вынесем в JSON + include_str! (уже помечено в design add-session-mvp).

## Open Questions

- Нужен ли показ обложки/иллюстрации к произведению — следующий change.
- Показывать ли название произведения на экране упражнения («Часть 2 из 6 · «Ворона и Лисица») — дешёвое улучшение, решение на apply: да, мелким заголовком.
