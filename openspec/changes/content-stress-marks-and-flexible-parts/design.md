# Design

## Context

Контент в `content/levels.json` / `content/stories.json`, core читает их через `include_str!`+serde ([content_data.rs](../../crates/core/src/content_data.rs)). Тесты core сейчас трёх видов по связи с данными: (1) инвариантные (`content_documents_are_valid`), (2) фиксирующие значения (`part_counts_are_recorded`: 27/14/16/12/15; комментарий «в vowels ровно 10» в `plan_repeats_when_size_exceeds_pool`; «10 односимвольных примеров» в `speed_is_chars_per_minute`), (3) чистые механические. Пользователь расставил ударения (U+0300/U+0301) и изменил разметку — упали (1) из-за алфавита и (2) по своей природе. UI число частей уже берёт из `stories_json().parts`.

## Goals / Non-Goals

**Goals:**
- Правка контента (содержание, количество, ударения) никогда не требует правки кода/тестов.
- Инварианты остаются строгими: пустой уровень/битый JSON/один кусок у басни по-прежнему падают.
- Механика (повторы плана, скорость) тестируется на данных, которые редактор контента не тронет.

**Non-Goals:**
- Разделение буквы и ударного знака (NFC/NFD нормализация, «ё vs е»), морфологический анализ.
- UI-отображение ударений особым стилем; рантайм-редактирование контента.

## Decisions

1. **Алфавит**: к разрешённым символам добавляем ровно `\u{300}` и `\u{301}` (то, что реально используется в русской типографике ударений). Альтернатива «разрешить все комбинирующие метки» отвергнута: шире дыра для опечаток. Проверка «≥2 ненулевых частей», непустота уровней, уникальность id — без изменений.
2. **Удалить `part_counts_are_recorded` совсем**, а не обновить числа: фиксация количеств противоречит цели (данные пользовательские). Минимальный инвариант «≥2 частей» уже покрыт `content_documents_are_valid`.
3. **Механические тесты — на синтетике.** `session_plan` принимает уровень из реального контента; чтобы тесты повторов/скорости не зависели от JSON, вводим #[cfg(test)]-хелпер `plan_from_pool(&[&str], size, seed)` — тот же Fisher-Yates-алгоритм, но поверх переданного пула (вынести тело генерации в приватную функцию, публичный API не меняется). `plan_repeats...` и `speed_is_chars_per_minute` вызывают хелпер с пулами вида `["а","о"]`×n; тесты скорости/нуля времени получают детерминированные длины символов независимо от того, сколько гласных добавит взрослый.
4. **Тест «изменение разметки басни»** реализуется как инвариантный: `story_part_count(id) == story.parts.len()` для всех произведений + отдельный unit-тест `Session::with_story(Text)` берёт total из документа (уже есть `session_text_walks_story_in_order`, он использует accessor, а не литерал — оставляем). Литеральных чисел в тестах уровня Text быть не должно (кроме зашитого fallback-id «первая история»).
5. **Регрессия UI не нужна**: `parts` в stories_json уже длина массива; vitest-ожидание «12» для martyshka — единственное место в web, где число частей литеральное; заменяем на чтение из `listStories()` в самом тесте (тест перестаёт зависеть от содержимого).

## Risks / Trade-offs

- [Пул-хелпер дублирует вызов RNG-функции] → один общий приватный путь, тесты и прод-код используют одну реализацию — расхождение невозможно.
- [Разрешение U+0300/U+0301 пропустит случайную расстановку ударений не на гласных] → осознанно: это вопрос качества контента (взрослый-вычитчик), не валидности формата.
- [Отказ от фиксации чисел частей теряет «колокольчик» на случайной склейке строк] → компромисс по требованию пользователя; минимальный инвариант ≥2 остаётся.

## Open Questions

- Нужен ли будет когда-нибудь тест «ударение стоит после гласной» — только если появятся жалобы на битую типографику; здесь не делаем.
