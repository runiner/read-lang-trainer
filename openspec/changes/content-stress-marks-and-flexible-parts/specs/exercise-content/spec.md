# Spec Delta

## MODIFIED Requirements

### Requirement: База примеров размечена по уровням
Система SHALL хранить базу примеров во внешних JSON-документах, включаемых в сборку: пять уровней «гласные», «простые слоги», «слоги», «слова», «фразы» — массивы текстов для чтения вслух (кириллица); уровень «текст» — массив произведений с id, названием, автором и списком частей. Каждый пример относится ровно к одному из шести уровней. Пустые строки-части игнорируются; содержимое документов является единственным источником упражнений. Количество упражнений для произведения уровня «текст» равно длине его массива parts и определяется только документом.

#### Scenario: Пример на каждом уровне
- **WHEN** запрашиваются примеры любого из шести уровней
- **THEN** возвращается непустой набор примеров этого уровня

#### Scenario: Произведения уровня «текст»
- **WHEN** запрашивается список произведений уровня «текст»
- **THEN** возвращаются не менее двух произведений, у каждого есть название, автор и как минимум две ненулевые части

#### Scenario: Добавление упражнения правкой документа
- **WHEN** взрослый добавляет строку в массив уровня или новый объект произведения в JSON-документ и пересобирает приложение
- **THEN** упражнение появляется в выборке без изменения кода

#### Scenario: Изменение разметки басни
- **WHEN** взрослый меняет число частей существующего произведения (склейка/разбиение строк) или добавляет новое произведение
- **THEN** приложение и проверки контента проходят без каких-либо правок кода или тестов, а сессия использует новое число частей

### Requirement: Корректность контентных документов
JSON-документы контента SHALL проходить проверку при сборке/тестах: валидный синтаксис, каждый уровень непустой, id произведений уникальны, у каждого произведения ≥2 ненулевых частей, все тексты состоят из кириллицы, разрешённой пунктуации и комбинирующих ударных знаков U+0300/U+0301 внутри слов. Проверки формулируются как инварианты структуры и алфавита и НЕ зависят от конкретных значений данных (количеств примеров и частей). Битый или невалидный документ делает сборку/тест неуспешными — приложение не подменяет его молча значениями по умолчанию.

#### Scenario: Битый JSON
- **WHEN** контентный документ содержит синтаксическую ошибку
- **THEN** тест контента падает с явной ошибкой парсинга

#### Scenario: Пустой уровень
- **WHEN** в документе массив какого-то уровня пуст
- **THEN** проверка завершается ошибкой с указанием уровня

#### Scenario: Слово с ударением
- **WHEN** в примере стоит слог с ударным знаком (например «сло́во»)
- **THEN** проверка считает текст допустимым, а статистика засчитывает ударный знак как символ текста
