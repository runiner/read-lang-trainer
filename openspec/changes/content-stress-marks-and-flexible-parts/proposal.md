# Proposal

## Why

Правка контента (расстановка ударений, изменение разметки басен) ломает `cargo test`, хотя данные корректны: валидатор контента не знает про комбинирующие ударные знаки U+0300/U+0301, а тесты завязаны на точные количества примеров и частей (`part_counts_are_recorded` фиксирует 27/14/16/12/15, `plan_repeats_when_size_exceeds_pool` — «в vowels ровно 10 уникальных», `speed_is_chars_per_minute` — «10 односимвольных примеров»). Контент — пользовательские данные: менять его нельзя, требуя правки кода/тестов.

## What Changes

- Разрешённые символы контентных документов включают ударения: U+0300 (combining grave) и U+0301 (combining acute) как часть слова; они не влияют ни на подбор, ни на подсчёт символов в статистике (символ есть символ).
- Валидность контента проверяется инвариантами, не зависящими от конкретных данных: непустота уровней, ≥2 частей у произведения, уникальность id, алфавит. Убираются проверки точных чисел: фиксация количеств частей каждой басни удаляется из тестов совсем.
- Тесты механики переписываются на синтетические данные вместо реального контента: план с повторами и расчёт скорости проверяются на маленьких искусственных наборах, которые редактор контента не может сломать. Реальный JSON остаётся под проверкой только через инварианты.
- UI уже берёт число частей из `stories.json` (`stories_json().parts`) — поведение подтверждается без изменений.

## Capabilities

### New Capabilities

_(нет)_

### Modified Capabilities

- `exercise-content`: требование «Корректность контентных документов» — алфавит дополняется ударными знаками, добавляется принцип «проверки не зависят от содержимого данных»; к требованию «База примеров…» уточняется источник числа частей для UI (длина массива parts документа).

## Impact

- `crates/core/src/session.rs`: тесты — `content_documents_are_valid` (белый список +U+0300/U+0301), удаление `part_counts_are_recorded`, перевод `plan_repeats_when_size_exceeds_pool`/`speed_is_chars_per_minute` на синтетику (нужен тестовый конструктор плана по произвольному списку или вызов с mock-уровнем — решает design).
- Код рантайма (подбор, сплит частей, статистика, фасад, UI) не меняется — ударения проходят сквозь него как обычные символы.
- Контент: текущие правки пользователя (ударения, Ворона 26 частей) остаются как есть, ничего не откатывается.
