# Design

## Context

Весь стиль — один файл [style.css](../../web/src/style.css) (~116 строк, плоские правила без системы); разметка экранов генерируется строками в `renderSettings/renderExercise/renderStats` ([main.ts](../../web/src/main.ts)). Тесты jsdom завязаны на id (`#size`, `#story`, `#start`, `.exercise .text`, `.story-title`, `#history-block`) и классы (`.screen settings/exercise/stats`, `.case-upper`, `#exercise-area`) — их переименовывать нельзя. Решения пользователя: минимализм «в духе SO», но своя палитра; анимаций нет вообще. Текущий UI уже удовлетворяет требованиям a11y из спеков (44px цели, viewport, фокус) — новая тема обязана сохранить это как нижнюю границу.

## Goals / Non-Goals

**Goals:**
- Один слой токенов правит всё; ре-тема = правка блока `:root`.
- Спокойная «документная» эстетика: белый/почти-белый фон, карточка с тонкой границей, серые подписи, один тёплый акцент.
- Нулевая функциональная диффа: ни одного изменения поведения/структуры DOM, кроме добавления классов-обёрток.

**Non-Goals:**
- Анимации, тени-«слои», тёмная тема, дизайн-система с документацией, CSS-фреймворки/постпроцессоры.
- Изменение наборов шрифтов (select остаётся), размеров целей нажатия ниже 44px, регистр/размеры текста упражнений вне clamp-правил.

## Decisions

1. **Токены в `:root`** (CSS custom properties): палитра — `--bg #fafafb` (страница), `--surface #fff` (карточка), `--border #e3e6e8`, `--text #232629`, `--muted #6a737b`, `--accent #c9531e` (тёплый терракотовый — дружелюбнее SO-оранжевого, контраст к белому ~5.0:1 для крупного текста кнопки + белый текст на нём), `--warn #b3261e`; шкала `--space-1..4` (4/8/16/24), радиусы `--radius 6px`, типошка `--fs-caption .. --fs-hero` (упражнение остаётся clamp(3.5rem,18vw,9rem)). Все правила дальше оперируют только переменными.
2. **Карточка вместо «всё на фоне»**: `.screen.settings > *` оборачивается в существующую `<section class="screen">` → добавляем вёрстку `.card` одной обёрткой в renderSettings (DOM-дифф: div.card вокруг полей; id не двигаются). Экран упражнения — без рамки (текст сам герой), вторичные надписи `--muted`. Статистика — карточка со списком метрик разделёнными строками (border-bottom вместо bullet-маркеров).
3. **Состояния**: `button:focus-visible { outline: 2px solid var(--accent); outline-offset: 2px }` (не убираем нативный outline — просто задаём цвет); hover затемнение акцента `color-mix(in srgb, var(--accent) 88%, black)`; readonly/select-disabled: `background: var(--bg); color: var(--muted)` — визуально «неактивно», читается. Подсказки ошибок (`.hint,.warn`) — `--warn`, caption-кегль.
4. **Статичность гарантируется тестом**, а не комментарием: css-тест проверяет отсутствие подстрок `transition:`/`animation:`/`@keyframes` в style.css (кроме `prefers-reduced-motion`— не нужен вовсе). Плюс grep-защита от возврата.
5. **Контраст**: пары фиксируем таблицей в комментарии токенов и проверяем только вручную глазами+инструментом на apply (jsdom контраст не считает); автоматизируем позже при желании.
6. **Никаких новых зависимостей/сборки**: чистый CSS, Vite как есть.

## Risks / Trade-offs

- [Терракотовый акцент может «кричать» на детском экране] → единственное место окраски — основная кнопка; если не понравится после прогона, меняется одна переменная `--accent`.
- [Обёртка .card ломает селекторы jsdom-тестов] → тесты ищут по id/классам элементов, структура внутри section не меняет их видимость; прогон vitest — арбитр.
- [Ручная проверка контраста — слабое звено] → принято для косметического change; автоматизация через axe-puppeteer описана в Open Questions.

## Open Questions
