# Design

## Context

Проект пустой (кода ещё нет), это первый change. Мотивация и скоуп — в proposal.md; требования — в четырёх спеках. Ограничения: офлайн-приложение без бэкенда, целевая платформа — браузер на устройстве с взрослым рядом.

## Goals / Non-Goals

**Goals:**
- Один рабочий пайплайн: Rust-логика → wasm → TS UI, минимальный код прослойки.
- Логика (контент, генерация сессий, статистика) тестируется без браузера.
- Стабильная граница wasm/JS: один типизированный фасад.

**Non-Goals:**
- Распознавание речи, звук, таймбокс — вне этого change.
- Редактирование базы примеров пользователем, несколько профилей ребёнка.
- CSS-полировка и дизайн-система: минимум читаемой крупной вёрстки достаточно. Мобильная адаптивность при этом в скоупе (см. spec `session-run`: viewport, цели нажатия ≥44px, без горизонтального скролла).

## Decisions

1. **Монорепозиторий cargo workspace**: `crates/core` (чистый Rust: `Level`, `Example`, `SessionPlan`, `SessionStats`) + `crates/wasm` (wasm-bindgen обёртки). Альтернатива — всё в одном crate с фичей `#[cfg(target_arch)]` — отвергнута: разделять тесты от wasm проще двумя crate'ами (`cargo test -p rus-core` идёт за секунды).
2. **Где localStorage**: чтение/запись истории делает JS на стороне `web/`, а сериализацию записи определяет core как `SessionRecord { date, level, count, duration_ms, chars_per_min }` → JSON через wasm-фасад. Альтернатива (web-sys из Rust) отвергнута: TS-сторона остаётся тонким адаптером, localStorage легко мокнуть в vitest.
3. **Состояние сессии живёт в Rust** (`core::Session`: курсор, порядок примеров, старт-время, отметки окончания каждого упражнения). UI лишь вызывает `next(elapsed_ms)` / читает текущий элемент. Альтернатива «всё состояние в TS» отвергнута: тогда core нечем заниматься, и логика дублируется при портировании.
   - Скорость чтения: время упражнения k = интервал от его показа до перехода к k+1 (тайминг по тому же «Далее», отдельной кнопки «Прочитал» нет). Итог: `Σ chars(примеры) / Σ elapsed` в символах в минуту; `chars_per_min = None`, если Σ elapsed = 0. Длительность сессии = Σ elapsed (не wall-clock настроек).
4. **Генерация порядка упражнений**: перемешивание Fisher-Yates с seed от `getrandom`(js) → передаётся в core как u64. Детерминизм по seed = тестируемость. Повтор при нехватке уникальных примеров: цикл по перемешанному списку.
5. **База примеров** — статический массив в `crates/core/src/content.rs`, константы по уровням (~10–30 примеров на уровень для старта). Альтернатива JSON-файл + include_str! — оставлена на будущий change редактирования.
6. **Управление**: глобальный `keydown` Space + кнопка `<button>Далее</button>` + `click/tap` по области упражнения — все шлют одно событие фасаду (тап = «Далее», без двойного срабатывания: обработчик один, клик по кнопке не дублируется). Экран настроек — нативные `<input type=number min=1 max=50>` и `<select>` из 5 уровней: валидация диапазона бесплатна, a11y из коробки. Мобильная адаптивность: `<meta viewport>`, flex/vh-вёрстка без горизонтального скролла, цели нажатия ≥44px, крупные `rem`-шрифты; отдельного CSS-фреймворка нет.
7. **Сборка**: `./tools/wasm-pack build crates/wasm -t web` → `web/pkg/`, Vite импортирует pkg как модуль. Запуск: `npm --prefix web run dev`.

## Risks / Trade-offs

- [wasm-pack/web-sys first-time pain] → MVP-фасад минимальный (5–6 экспортов), при проблемах локалу можно временно реализовать на TS без смены спецификации.
- [Фикстуры контента «на глаз», носитель языка не проверял] → контент вынесен в отдельный модуль одним PR-блоком задач; правки после теста на ребёнке.
- [localStorage лимит ~5 МБ] → запись сессии <200 байт, история обрезается до последних 500 записей.
- [Пробел перехватывается инпутами] → keydown игнорирует событие, если фокус в элементе ввода.
- [Тап по области упражнения срабатывает и при клике по кнопке «Далее» (двойной переход)] → один обработчик на контейнер экрана; кнопка внутри него не имеет собственного слушателя перехода.
- [Взрослый жмёт «Далее» с задержкой после прочтения → скорость занижена] → это осознанное приближение: замер включает реакцию; отдельная кнопка «Прочитал» оставлена как будущий refinement.
