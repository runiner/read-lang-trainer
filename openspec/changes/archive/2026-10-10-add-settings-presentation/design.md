# Design

## Context

Приложение уже работает (change `add-session-mvp`): экран настроек собран в `web/src/main.ts` (`renderSettings`), история сессий лежит в localStorage через `web/src/history.ts` (ключ `rus-trainer.sessions`). Состояние сессии и подсчёт символов живут в Rust-core; UI получает текст через JSON из `web/src/wasm.ts`. См. proposal.md — зачем нужны методика, шрифт и регистр.

## Goals / Non-Goals

**Goals:**
- Настройки отображения — чистая презентация: не трогают core, план сессии и статистику.
- Один механизм хранения предпочтений рядом с историей, тот же fallback при недоступном хранилище.
- Выбор шрифта виден мгновенно (предпросмотр), без перезапуска.

**Non-Goals:**
- Отдельные наборы примеров под прописную/строчную азбуку (решено: только начертание).
- Настройка размера шрифта, цвета темы, тёмного режима.
- Импорт своих шрифтов пользователем.

## Decisions

1. **Регистр = CSS, а не трансформация текста.** Для области упражнения вводится класс `.case-upper { text-transform: uppercase; }`, висящий на контейнере экрана. Причина: статистика считает символы в Rust по исходному тексту; если перевернуть регистр в core или в JS до передачи, легко задеть длину (например `ё`→`Ё`) и смешать презентацию с моделью. Альтернатива `String.toUpperCase()` в фасаде отвергнута как лишняя работа и риск рассинхрона с предпросмотром.
2. **Шрифт — CSS custom property.** `--ui-font` на `<html>`, значения из фиксированного списка стеков: `system-ui` (дефолт), `Georgia, serif` и ещё один рубленый стек. Никаких загружаемых веб-шрифтов: офлайн-приложение, и системные стеки закрывают «несколько читаемых вариантов». Альтернатива (пакет шрифтов в web/public) оставлена как будущий refinement, если окажется, что системных мало.
3. **Где живут предпочтения.** Новый модуль `web/src/preferences.ts` с ключом `rus-trainer.preferences` и тем же storage-адаптером, что и история: `{ fontId, letterCase, methodologySeen }`. Не расширяем `SessionRecord`: это данные занятия, а не устройства.
4. **Методика — `<details>` внутри экрана настроек**, свёрнут по умолчанию; после первого раскрытия запоминается `methodologySeen=true` и блок остаётся свёрнутым (уже прочитан). Отдельного требования «показывать всегда» нет — текст короткий.
5. **Что сбрасывается.** Размер сессии и уровень — каждый запуск дефолтные (режим занятия выбирается заново); шрифт/регистр/методика — сохраняются. Это разделение прямо зафиксировано в спеке.
6. **Порядок контролов в окне настроек:** методика → размер → уровень → шрифт → регистр → «Начать» → история. Мелкая правка разметки `renderSettings`, обработчик старта не меняется.

## Risks / Trade-offs

- [`text-transform` не влияет на ввод/копирование — ребёнок видит «МАМА», в DOM остаётся «мама`] → осознанно: для чтения вслух важно начертание; тест сверяет видимый текст через `getComputedStyle`.
- [Системные стеки выглядят по-разному на разных устройствах] → список стеков короткий и заведомо читаемый; реальный подбор проверяется прогоном на устройстве ребёнка.
- [Два ключа в localStorage могут разойтись при ручном редактировании] → парсер предпочтений игнорирует неизвестные поля и возвращает дефолты.

## Open Questions

- Нужен ли отдельный крупный «прописной» шрифт с буквами, похожими на рукописные — следующий change после теста на ребёнке.
