# Design

## Context

Баг подтверждён в коде: [main.ts](../../web/src/main.ts) заполняет `storySel.innerHTML` только при `stories.length === 0` (разовое наполнение кэша), а `renderSettings()` каждый раз пересоздаёт DOM select'а — после возврата из сессии кэш непустой, populate пропускается, select остаётся без опций. Метрика скорости сейчас символьная: `Session::finish` считает `total_chars * 60_000 / elapsed` и кладёт в `SessionRecord.chars_per_min`; UI печатает «символов в минуту» на экране статистики и «симв/мин» в истории. См. proposal.md — что меняется и почему слова привычнее взрослому.

## Goals / Non-Goals

**Goals:**
- Две Text-сессии подряд без перезагрузки работают; баг закрыт сквозным тестом, который до фикса был бы красным.
- Слова считаются по одному определению в core (Rust); JS нигде не пересчитывает.
- Старые localStorage-записи не ломают историю.

**Non-Goals:**
- Миграция старых записей, отображение их скорости «как-нибудь иначе».
- Настройка порога слов/мин, цветовой индикатор темпа.
- Изменение определения «времени упражнения» (по-прежнему интервал до «Далее»).

## Decisions

1. **Фикс бага — declarative populate.** Убираем условие-кэш вокруг наполнения select: `renderSettings()` всегда строит опции из `listStories()` (стоимость — вызов facade ~µs). Кэш массива `stories` остаётся для поиска по id. Альтернатива «не пересоздавать DOM» отвергнута: вся архитектура экрана — innerHTML-рендер, один частный случай против неё бесполезен.
2. **Определение слова в core.** `fn count_words(text: &str) -> usize`: идём char-итератором, слово = максимальная подпоследовательность символов, где буквы (`c.is_alphabetic() && кириллица/ё`) могут быть смежны через дефис, если слева и справа буква («по-братски» = 1). Ударные U+0300/U+0301 следуют за буквой и относятся к слову. Реализация — конечный автомат «в слове / вне слова», ~15 строк, тестируется напрямую. Python-подобные regex-альтернативы в Rust потребовали бы crate regex — не заводим ради этого.
3. **Схема записи.** `SessionRecord { …, words_per_min: Option<u32> }` — переименование поля (не добавление второго): формат локальный, миграции нет по решению пользователя. JS-тип `SessionRecord.words_per_min?: number | null`; история рендерит прочерк, когда поля нет вообще (старая запись) или оно null.
4. **Накопление в Session.** `total_words` считается по плану так же, как `total_chars` (один проход при создании); `chars_per_min` из record исчезает полностью — держать два показателя YAGNI, экран показывает один.
5. **Тест до фикса (red-first).** В задачах отдельным пунктом: e2e-тест «два запуска text-сессии подряд» сначала прогоняется против текущего кода и должен упасть (подтверждение диагноза), затем после фикса зелёный. Тесты слов: «мама мыла, — говорит, — раму»=4, «по-братски»=1, «сло́во»=1, пустая строка=0.

## Risks / Trade-offs

- [Дефисное написание двусмысленно («что-то», «по-братски» vs составные)] → принято: одна единица; покрыто тестом; при жалобах правится в одном месте core.
- [Потеря информации в старых записях (прочерк вместо чисел)] → осознанно пользователем; данные демонстрационные.
- [`is_alphabetic` шире кириллицы] → контент проходит валидацию алфавита (spec exercise-content), латиница в данных невозможна — риск теоретический; при желании сузим до диапазона U+0400–U+04FF.
