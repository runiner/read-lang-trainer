# Design

## Context

Контент сейчас — Rust-константы: `content.rs` (5 массивов `&[&str]`) и `stories.rs` (`STORIES: &[Story]`, части внутри одной строки через `\n`). Core отдаёт их через `Level::examples()` и `story_parts()`. Приложение публикуется статикой на GitHub Pages, wasm собирается wasm-pack'ом. См. proposal.md — зачем выносить в JSON.

## Goals / Non-Goals

**Goals:**
- Контент правится одним файлом без прикосновения к Rust-логике.
- Нулевые рантайм-издержки и офлайн-режим сохранены.
- Ошибки контента видны на сборке, а не ребёнку.

**Non-Goals:**
- Загрузка JSON по HTTP в рантайме, импорт файлов браузером, UI-редактор, hot-reload контента.
- Смена схемы уровней/поведения сессий.

## Decisions

1. **include_str!, не fetch.** `crates/core/src/content_data.rs`: `const LEVELS_JSON: &str = include_str!("../../../content/levels.json");` + serde → `LazyLock<Content>` один раз при первом обращении. Альтернативы отвергнуты: fetch из web/public ломает единую границу «core знает контент» и добавляет async-init; cargo build-script генерировал бы код — сложнее отлаживать. Путь `../../../content/` фиксирует макет репо; перенос каталога — одна правка двух include.
2. **Два документа, не один.** `content/levels.json` — `{"vowels":[...],"simple-syllables":[...],...}` (ключи = id уровней); `content/stories.json` — `[{"id","title","author","parts":[...]}]`. Части басен становятся настоящим массивом строк — разметка «одна строка = часть» превращается в «один элемент = часть», читаемее и без ловушки `\n` в JSON. Отдельный файл на уровень отвергнут: 6 файлов плодят бойлерплейт include при нулевой выгоде.
3. **Парсинг падает громко.** `LazyLock` с `.expect("content/levels.json: …")` — panic при битом JSON. Поскольку тесты гоняются до деплоя в CI, пользователь битый документ не увидит; отдельного Result-API в core нет (YAGNI: источник данных контролируется нами).
4. **Валидность — тесты, не код.** Требование «Корректность контентных документов» реализуется unit-тестами core (непустота уровней, уникальность id, ≥2 частей, кириллица+пунктуация) + отдельным шагом `python -m json.tool content/*.json`? Нет — достаточно cargo-тестов: они парсят те же файлы, синтаксис покрыт автоматически.
5. **API core не меняется.** `Level::examples()` возвращает `&'static [&'static str]`? Нет — теперь данные живые: меняем сигнатуру на `&'static [String]` или accessor `level_examples(level) -> &'static [String]`; `session_plan` подстраивается минимально (уже работает со String). `Story.parts: Vec<String>` вместо text+split; `story_parts()` тривиализуется. Внешнее поведение (что видит wasm/UI) идентично.
6. **Миграция данных 1-в-1.** Текущие массивы и пять басен переносятся скриптом apply-задачи без изменения содержимого; числа частей (27/14/16/12/15) закрепляются тестом как раньше.

## Risks / Trade-offs

- [include_str! путь хрупок при перемещении каталогов] → путь только в одном модуле, комментарий-маяк; CI-тест ловит поломку мгновенно.
- [panic в LazyLock роняет всё приложение, если кто-то сломал JSON, минуя тесты] → тесты контента — часть `cargo test`, который стоит в CI до сборки; риск принят сознательно ради простоты.
- [Размер wasm +несколько КБ JSON] → несущественно против текущих ~70 КБ.
