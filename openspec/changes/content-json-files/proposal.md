# Proposal

## Why

Упражнения сейчас зашиты в Rust-константы (`content.rs`, `stories.rs`): чтобы добавить слово или пере-разметить басню, правят код и пересобирают core. Контент — данные, а не логика: его должен редактировать взрослый как простой документ, без прикосновения к Rust. Переносим весь контент в JSON-файлы репозитория, которые core читает на этапе сборки.

## What Changes

- В репозитории появляется каталог `content/`: `levels.json` (массивы примеров для уровней «гласные», «простые слоги», «слоги», «слова», «фразы») и `stories.json` (произведения уровня «текст»: id, название, автор, массив частей).
- Rust-core загружает эти документы через `include_str!` + serde-десериализацию при старте; статические константы `VOWELS/SIMPLE_SYLLABLES/.../STORIES` упраздняются как источник данных.
- Приложение остаётся офлайн-статикой: JSON компилируются в wasm-бинарь, отдельных HTTP-запросов к контенту нет; поведение всех шести уровней не меняется.
- Неверный JSON (битый синтаксис, пустой уровень, дубликаты id) — ошибка сборки/теста, а не молчаливый фолбэк.
- README получает инструкцию, как добавить упражнение или басню правкой JSON.

## Capabilities

### New Capabilities

_(нет)_

### Modified Capabilities

- `exercise-content`: база примеров хранится во внешних JSON-документах репозитория и загружается при сборке; требования по уровням, порядку частей и подбору остаются прежними поведению, меняется формулировка источника хранения; добавляется требование проверки корректности документов.

## Impact

- Новый каталог `content/levels.json`, `content/stories.json` (перенос существующих данных 1-в-1).
- `crates/core`: `level.rs`/`stories.rs` → модуль `content_json.rs` с serde-структурами и `LazyLock`-парсингом из `include_str!`; тесты контента переписываются на JSON-источник; поведение `session.rs` не меняется.
- Зависимости ядра: `serde_json` переезжает из dev-dependencies в runtime-зависимость core (уже есть в wasm).
- CI/сборка: не меняются (JSON внутри crate-данных); размер wasm +несколько КБ.
