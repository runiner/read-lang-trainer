# Design

## Context

Уровень «текст» реализован: `Story { id, title, author, text }` в [stories.rs](../../crates/core/src/stories.rs), границы частей считает DP-сплит по пунктуации (`split_sentences`/`story_fragments`/`story_parts` в [session.rs](../../crates/core/src/session.rs)), UI показывает поле размера 5–50 + hint «максимум N». См. proposal.md — почему переходим на ручную разметку.

## Goals / Non-Goals

**Goals:**
- Единственный источник границ части — человек-разметчик; алгоритм сплита удаляется без остатков.
- Максимально простой mental model для UI: выбрал текст → увидел число частей → начал.
- Обратная совместимость формата записи сессии (`level: "text"`, count = фактическое число частей).

**Non-Goals:**
- Редактор разметки в приложении, загрузка текстов из файлов, несколько вариантов разбиения одного текста.
- Изменение уровней, кроме «текст».

## Decisions

1. **Формат разметки.** `Story.text` остаётся единой строкой, часть = непустая строка после split по `\n` (trim каждой части). Хранить `parts: &[&str]` массивом — альтернатива; отвергнута: одна строка удобнее для переноса в будущий JSON, а accessor `story_parts()` тривиален. Пустые строки игнорируются; требование «≥2 части» на уровне теста контента.
2. **Удаление авто-сплита.** `split_sentences`, `story_fragments`, `story_parts(DP)`, `sum_lens`, `nearest_cut`, `glue_small` и их unit-тесты удаляются из core. `Session::with_story(Text)` строит план напрямую из частей; параметр `size` для Text игнорируется (UI его не отправляет значимым). Фасад `create_session` сигнатуру не меняет — меньше дёргания web/wasm.
3. **stories_json.** Поле `maxParts` переименовывается в `parts` (число размеченных частей) — честное имя: это не максимум, а размер. TS-тип `StoryInfo.maxParts` → `parts`.
4. **UI настроек.** При `level === 'text'`: контейнер поля размера получает `hidden`, рядом со списком произведений показывается строка «Сессия: N упражнений» (обновляется при смене select); старт блокируется только отсутствием выбора произведения. Подсказка про «уменьшите размер» удаляется вместе с логикой. При возврате к другим уровням поле снова активно.
5. **Переразметка басен.** Каждая строка stories.rs = смысловая часть (реплика целиком, абзац-картинка). Ориентир 6–12 частей на басню — занятие из 5 минут чтения. Разметку делает агент, финальную вычитку — взрослый (помечаем `shortcut:`).
6. **Статистика не меняется**: chars считаются по concatenated частям — та же сумма символов, что раньше давал сплит того же текста.

## Risks / Trade-offs

- [Ручная разметка субъективна и может быть неровной по длине] → тест «части ≥2 и склейка строк = исходный текст» ловит только структуру, длину проверяем глазами при занятии; правится одной строкой в stories.rs.
- [Исторические SessionRecord содержали level:"text" со старым count] → формат не ломается, просто сравнивать «до/после» по count нельзя — приемлемо, истории демонстративные.
- [Размер >50 невозможен для очень длинных разметок] → басни короткие (<15 частей), ограничение диапазона UI на Text не действует — осознанно.

## Open Questions

- Не видно ли потом желание «прочитать только первые K частей» — если появится, отдельный change (K-подвыбор).
