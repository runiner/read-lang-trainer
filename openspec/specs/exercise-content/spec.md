# exercise-content Specification

## Purpose

Определяет встроенную базу примеров для чтения, размеченных по уровням сложности, и правила подбора упражнений в сессию.

## Requirements

### Requirement: База примеров размечена по уровням
Система SHALL хранить базу примеров во внешних JSON-документах, включаемых в сборку: пять уровней «гласные», «простые слоги», «слоги», «слова», «фразы» — массивы текстов для чтения вслух (кириллица); уровень «текст» — массив произведений с id, названием, автором и списком частей. Каждый пример относится ровно к одному из шести уровней. Пустые строки-части игнорируются; содержимое документов является единственным источником упражнений. Количество упражнений для произведения уровня «текст» равно длине его массива parts и определяется только документом.

#### Scenario: Пример на каждом уровне
- **WHEN** запрашиваются примеры любого из шести уровней
- **THEN** возвращается непустой набор примеров этого уровня

#### Scenario: Произведения уровня «текст»
- **WHEN** запрашивается список произведений уровня «текст»
- **THEN** возвращаются не менее двух произведений, у каждого есть название, автор и как минимум две ненулевые части

#### Scenario: Добавление упражнения правкой документа
- **WHEN** взрослый добавляет строку в массив уровня или новый объект произведения в JSON-документ и пересобирает приложение
- **THEN** упражнение появляется в выборке без изменения кода

#### Scenario: Изменение разметки басни
- **WHEN** взрослый меняет число частей существующего произведения (склейка/разбиение строк) или добавляет новое произведение
- **THEN** приложение и проверки контента проходят без каких-либо правок кода или тестов, а сессия использует новое число частей

### Requirement: Подбор упражнений по уровню
Система SHALL формировать последовательность упражнений сессии только из примеров выбранного уровня сложности. Для уровня «текст» упражнениями являются части одного выбранного произведения в порядке их следования в разметке.

#### Scenario: Сессия уровня «гласные»
- **WHEN** запущена сессия уровня «гласные» размером 8
- **THEN** показаны 8 упражнений, каждый пример состоит из гласных букв уровня

#### Scenario: Сессия уровня «текст»
- **WHEN** запущена сессия уровня «текст» с выбранным произведением
- **THEN** показано столько упражнений, сколько частей в разметке, и они по порядку воссоздают весь текст произведения

### Requirement: Размер сессии больше доступной базы
Если количество запрошенных упражнений превышает число уникальных примеров уровня, система SHALL повторять примеры до нужной длины. Это правило не применяется к уровню «текст»: там размер сессии задаётся разметкой частей одного произведения, а не отбором из множества примеров.

#### Scenario: Недостаточно уникальных примеров
- **WHEN** запрошена сессия из 50 упражнений уровня с 20 уникальными примерами
- **THEN** сессия содержит 50 упражнений, примеры повторяются

#### Scenario: Уровень «текст» без повторов
- **WHEN** сессия уровня «текст» содержит N упражнений
- **THEN** каждое упражнение — следующая часть того же произведения, порядок соответствует разметке

### Requirement: Корректность контентных документов
JSON-документы контента SHALL проходить проверку при сборке/тестах: валидный синтаксис, каждый уровень непустой, id произведений уникальны, у каждого произведения ≥2 ненулевых частей, все тексты состоят из кириллицы, разрешённой пунктуации и комбинирующих ударных знаков U+0300/U+0301 внутри слов. Проверки формулируются как инварианты структуры и алфавита и НЕ зависят от конкретных значений данных (количеств примеров и частей). Битый или невалидный документ делает сборку/тест неуспешными — приложение не подменяет его молча значениями по умолчанию.

#### Scenario: Битый JSON
- **WHEN** контентный документ содержит синтаксическую ошибку
- **THEN** тест контента падает с явной ошибкой парсинга

#### Scenario: Пустой уровень
- **WHEN** в документе массив какого-то уровня пуст
- **THEN** проверка завершается ошибкой с указанием уровня

#### Scenario: Слово с ударением
- **WHEN** в примере стоит слог с ударным знаком (например «сло́во»)
- **THEN** проверка считает текст допустимым, а статистика засчитывает ударный знак как символ текста

### Requirement: Свежесть собранного контента
Собранный wasm-артефакт SHALL содержать ровно тот контент, который находится в JSON-документах на момент сборки. Артефакт несёт встроенный идентификатор версии — детерминированную функцию от байтов всех контентных документов, доступную из пакета как отдельная функция. Автоматическая проверка (CI и тест против pkg) обязана падать при расхождении версии в пакете и посчитанной от текущих файлов: устаревший артефакт не может быть отдан пользователю незамеченным.

#### Scenario: Правка контента без пересборки попадает под проверку
- **WHEN** контентный документ изменён, а собранный пакет всё ещё содержит предыдущую версию контента
- **THEN** проверка свежести (CI или тест против pkg) падает с указанием расходящихся версий

#### Scenario: Актуальный артефакт проходит проверку
- **WHEN** пакет пересобран после последней правки контентных документов
- **THEN** версия контента в пакете равна версии, посчитанной от файлов, и проверка зелёная

#### Scenario: Версия меняется только вместе с контентом
- **WHEN** контентные документы не менялись, но пересобран код приложения
- **THEN** идентификатор версии контента остаётся прежним
