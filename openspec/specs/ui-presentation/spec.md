# ui-presentation Specification

## Purpose

Определяет визуальный язык приложения: палитру, типографику, структуру экранов и состояния контролов. Capability косметическая — она не задаёт и не меняет поведение функций, но обязывает все экраны выглядеть согласованно, спокойной сдержанной стилистикой и оставаться доступными.

## Requirements

### Requirement: Единый слой дизайн-токенов
Система SHALL определять внешний вид всех экранов через единый слой токенов (цвета, шкала размеров шрифта, отступы, скругления, границы), заданный в одном месте; ни один экран не использует произвольные цвета или размеры вне этого слоя. Палитра нейтральная и спокойная: светлый фон, тёмно-серый текст, тонкие серые границы, ровно один акцентный цвет для основных действий, контраст текста к фону не ниже 4.5:1.

#### Scenario: Акцент только у действия
- **WHEN** на экране есть основная кнопка («Начать», «Далее»)
- **THEN** она единственная окрашена акцентным цветом, остальные элементы нейтральны

#### Scenario: Контраст сохранён
- **WHEN** любой текст экрана отрисован по своей токенизированной паре «текст/фон»
- **THEN** отношение контраста не ниже 4.5:1

### Requirement: Согласованная структура экранов
Каждый экран приложения SHALL представлять каждый экран структурой «карточка по центру»: заголовок, группа контролов с подписями, основное действие внизу карточки; второстепенное (методика, история) — сворачиваемые секции внутри той же колонки. Отступы между группами кратно базовой единице из слоя токенов.

#### Scenario: Окно настроек как карточка
- **WHEN** открыто окно настроек
- **THEN** методика, размер, уровень, произведение, шрифт, регистр и «Начать» сгруппированы в одной центрированной карточке с равными отступами между полями

#### Scenario: Экран упражнения доминирует
- **WHEN** показано упражнение
- **THEN** текст примера занимает центр экрана крупным кеглем, счётчик и название произведения — приглушённым вторичным цветом, кнопка «Далее» под текстом

### Requirement: Явные состояния контролов
Интерактивные элементы SHALL иметь визуально различимые состояния: обычное, hover, фокус с клавиатуры (заметный контур focus-visible), disabled/readonly (например, поле размера при уровне «текст»), и подсказки об ошибке — одним стилем предупреждающего цвета поверх обычного текста.

#### Scenario: Фокус с клавиатуры виден
- **WHEN** пользователь доходит Tab'ом до кнопки
- **THEN** вокруг элемента появляется заметный контур фокуса, отличный от hover

#### Scenario: Неактивное поле размера отличается
- **WHEN** поле размера переведено в readonly при уровне «текст»
- **THEN** оно визуально выглядит неактивным (приглушённый фон/текст), но остаётся читаемым

### Requirement: Статичность интерфейса
Система SHALL мгновенно переключать экраны и не использовать анимаций или переходов (transition/animation) в оформлении; изменение состояния элемента заметно мгновенной сменой цветов/границ. Ограничение не распространяется на празднование capability `celebration`: оно — единственное место, где движение допустимо, и только пока активно.

#### Scenario: Смена упражнения без перехода
- **WHEN** ребёнок перешёл к следующему упражнению
- **THEN** новый текст появляется мгновенно, без затухания или сдвига

#### Scenario: Празднование — разрешённое исключение
- **WHEN** активно празднование
- **THEN** движущиеся элементы появляются только внутри его оверлея, а оформление базового экрана остаётся статичным
